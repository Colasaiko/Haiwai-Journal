遇到“连接家里或者公司的 Wi-Fi 时，代理软件（机场）可以顺畅地科学上网，但是一旦出门切换到手机移动数据（4G/5G），软件就死活连不上、网页打不开”的情况吗？这个问题在代理用户群体中非常普遍。产生这种现象的根本原因在于，Wi-Fi 和移动数据不仅是两种不同的物理接入方式，它们背后的网络环境、运营商策略、DNS 解析路径、IP 协议版本（IPv4/IPv6）甚至设备针对它们分配的应用权限都有着天壤之别。下面我们将从最基础的权限设置到深度的 APN 协议层面，为你提供一份详尽的排查指南，帮你彻底解决手机流量下无法使用网络节点的问题。

## 典型的问题表现

在排查之前，我们首先需要确认你遇到的情况是否符合以下几种典型的问题表现：

1. **软件状态显示已连接，但无实际数据收发**：代理客户端的开关已经打开，甚至系统状态栏也出现了 VPN 的钥匙图标，但在浏览器中输入任意国外网址，始终处于加载中，最后提示“连接超时（Connection Timed Out）”。
2. **国内外网站全部断网**：只要在 4G/5G 状态下开启代理，不仅 YouTube、Google 等海外网站打不开，连百度、微信等国内应用也提示网络异常，必须关闭代理才能恢复。
3. **部分节点能用，部分节点失效**：在 Wi-Fi 环境下所有节点都是绿色的全通状态，而在移动网络下，只有特定的几个节点能够勉强连接，延迟奇高，甚至频繁断线。
4. **网络切换时假死**：从家里的 Wi-Fi 环境走到户外自动切换到 5G 网络时，代理软件不会自动重连，必须手动关闭再打开一次才能恢复正常。

## 最可能的原因分析

很多新手在遇到这个问题时，第一反应往往是“我的运营商把这个机场封锁了”。但实际上，虽然存在运营商层面的网络干预，但这并不是唯一且绝对的原因。以下是导致该问题最核心的几个因素：

*   **IPv4 与 IPv6 的环境差异**：现代的 4G/5G 移动网络默认且强制分配 IPv6 地址，而大部分家庭 Wi-Fi 依然以 IPv4 为主。很多机场的节点或代理客户端的内置路由规则未能完美兼容纯 IPv6 环境。
*   **权限与系统限制**：智能手机（尤其是国产 Android 系统和 iOS 系统）对移动数据和后台运行有着严格的电量与流量控制。代理软件可能根本没有被授予在移动网络下使用数据或建立系统级 VPN 的权限。
*   **DNS 污染与解析差异**：移动网络下的基站 DNS 与家用宽带的 DNS 完全不同，移动运营商的 DNS 劫持和污染情况往往更为复杂，可能导致代理软件无法解析到节点的真实入口 IP。
*   **网络切换（Network Switching）逻辑滞后**：代理软件建立的 TUN/TAP 虚拟网卡在底层网络（从 Wi-Fi 到蜂窝网络）发生物理切换时，可能未能及时刷新路由表，导致流量依然在寻找已经断开的 Wi-Fi 接口。

## 一分钟快速检查

在进行复杂的底层设置修改之前，请先尝试以下几个“一分钟快速排查”步骤，往往能解决 50% 以上的偶发性故障：

1. **开关飞行模式**：开启手机的飞行模式，等待 10 秒钟后再关闭，强制手机重新连接移动基站并获取全新的 IP 地址和网络状态。
2. **重启代理软件和手机**：彻底退出代理客户端（在多任务卡片中划掉），然后再重新打开。如果无效，直接重启手机以重置系统的网络缓存。
3. **确认基础网络畅通**：关闭代理软件，确认在使用 4G/5G 移动数据时，微信、百度等国内应用能够正常收发消息和浏览网页。如果国内网络也断开了，说明是手机欠费或基站信号问题，而非代理软件的锅。
4. **更新订阅与重启节点**：在移动网络下，手动点击代理软件内的“更新订阅”按钮，并尝试切换至其他地区或其他类型的节点。参考 [什么是节点线路](/network/what-is-proxy-node-routing) 了解如何筛选优质节点。

## 步步为营：深度排查与修复指南

如果上述快速检查未能解决你的问题，请严格按照以下步骤进行深度排查。

### 第一步：检查并开放必要的系统权限

不管是 Android 还是 iOS 系统，代理软件都需要极为底层的权限才能接管全局流量。

**针对 iOS（iPhone/iPad）用户：**
1. 进入系统设置，向下滑动找到你的代理软件（如 Shadowrocket、Quantumult X、Loon 等）。
2. 确保**“蜂窝网络”（移动数据）**开关是处于开启状态的。如果在系统刚安装时你不小心点击了“仅允许在无线局域网下使用”，软件将直接被切断 4G/5G 流量。
3. 进入设置 -> 通用 -> VPN 与设备管理，确认软件的配置已经被正确安装并处于活跃状态，确保系统 VPN 权限没有被其他安全软件拦截。

**针对 Android 用户：**
1. 进入系统设置 -> 应用管理，找到你使用的代理客户端（如 Clash、v2rayNG、Surfboard）。
2. 进入“流量使用情况”或“联网权限”，确保勾选了**“移动数据”**，并且允许其在后台使用移动数据。
3. 进入“电池”或“省电策略”，将该软件设置为**“无限制”或“允许后台高耗电”**。由于 Android 系统为了省电，经常会在用户切换到移动数据（且息屏）时强行杀掉或冻结耗电的客户端后台进程，导致连接中断。

### 第二步：排查 IPv6 与修改 APN 设置（关键！）

这是移动网络无法科学上网最常见的“罪魁祸首”。国内三大运营商的 4G/5G 网络目前基本都默认开启并优先使用 IPv6，如果你的代理节点仅支持 IPv4，或者客户端对 IPv6 的流量路由处理存在 bug，就会出现无法连接的现象。想深入了解可以阅读 [IPv6 对科学上网的影响](/network/ipv6-impact-on-proxy)。

**解决方法：新建一个仅支持 IPv4 的 APN（接入点名称）**
对于 Android 用户，可以通过更改 APN 协议来强制手机移动网络回退到兼容性最强的 IPv4 模式。

1. 进入 Android 系统设置 -> 双卡与移动网络 -> 找到你正在使用的 SIM 卡 -> **接入点名称 (APN)**。
2. 你可能会看到当前正在使用的是类似 `ctnet`、`3gnet` 或 `cmnet` 的默认接入点。点击它进入编辑模式，或者点击右上角的“新建 APN”。
3. 如果是新建，名称可以随意填写（如“IPv4 APN”），APN 字段填入你运营商的默认值（移动填 `cmnet`，联通填 `3gnet`，电信填 `ctnet`）。
4. 向下滚动，找到 **“APN 协议”** 和 **“APN 漫游协议”**。
5. 将这两个选项从默认的 `IPv4/IPv6` 修改为纯粹的 **`IPv4`**。
6. 点击保存并应用这个新的 APN，手机信号栏会短暂消失然后重连。之后再次打开代理软件，测试是否恢复正常。

> 注：iOS 系统不开放用户手动修改 APN 协议栈的权限，如果 iOS 遇到此类问题，建议在代理客户端的设置中（如 Shadowrocket 的通用设置）关闭“Enable IPv6”或者设置“IPv6 路由”为“停用（Disable）”。

### 第三步：解决 DNS 污染与解析失败

移动网络的 DNS 环境往往比固网宽带更差，很多时候节点域名在 5G 下被解析到了错误的 IP 地址。你可以参考 [DNS 泄露与防范](/security/dns-leak-prevention) 了解相关原理。

1. **将客户端内的 DNS 设置为安全的公共 DNS**：在代理客户端的 DNS 设置中，不要使用“系统默认 DNS”，而是手动指定为 `223.5.5.5`（阿里）、`119.29.29.29`（腾讯）或者直接使用 `8.8.8.8` / `1.1.1.1`（前提是你的客户端支持远端解析）。
2. **启用“绕过局域网及大陆地址”或“规则模式”**：确保你没有使用“全局模式（Global）”，因为全局模式下，连国内的 DNS 请求甚至微信流量都会被强行打包发给国外节点，不仅速度极慢，还极容易触发运营商的安全风控，导致短暂断网。

### 第四步：更换节点线路与防封锁测试

虽然我们不认为问题总是出在运营商封锁上，但不可否认的是，某些特定省份的移动运营商（尤其是中国移动的部分地区）对出国流量的阻断策略确实比电信和联通更为激进。

*   **测试不同端口的节点**：如果你的机场提供多个端口（如 80、443、8080 及高位端口），在移动网络下尝试切换。运营商有时会封锁特定高位端口上的大流量特征。
*   **切换不同的传输协议**：老旧的 Shadowsocks（SS）协议在部分省份的 5G 网络下基本做到秒级阻断。尝试使用伪装性更好的协议（如 Trojan、Vless + XTLS、Hysteria2）。详情可见 [Clash/V2ray 客户端选择指北](/client/how-to-choose-proxy-client)。
*   **测试专线节点**：如果你使用的是直连节点，在 5G 下可能因为跨网路由极差而丢包 100%。尝试切换到带有“IPLC”或“IEPL”标志的内网专线节点，专线入口在国内，不受国际出口阻断影响。

## 不同场景下的特殊情况与补充建议

*   **频繁在 Wi-Fi 和数据间切换（网络切换问题）**：当你的设备从 Wi-Fi 断开并接入 4G/5G 时，底层网络接口（Interface）发生了根本改变，但代理软件建立的虚拟连接可能仍在“死等”原本的 Wi-Fi 接口恢复。此时表现为无论国内外网页都打不开。一般的客户端（如 Clash Meta / Sing-box 核心）有连接存活检测机制，但反应可能较慢。遇到此类情况，最快的方法就是下拉通知栏，把代理开关关掉再重新打开，强制其重新绑定当前活跃的网络接口。
*   **公司/校园 5G 专网冲突**：部分用户手机使用的是具有校园专网或企业内部专网属性的 5G 卡，这类网络本身带有强制的 VPN 隧道或特定的路由规则。在此类网络下运行个人代理软件，几乎必然发生路由表冲突。这种情况一般无法通过简单的设置解决。

## 如果以上方法都不起作用怎么办？

如果你已经穷尽了上述所有的排查步骤，但问题依然如故，建议采取以下终极测试方案：

1. **交叉验证**：将你的代理订阅链接发给身边的朋友（最好使用不同运营商的移动卡，以及不同操作系统的手机），看对方在移动网络下能否正常使用。如果在别人手机上一切正常，说明大概率还是你本机的系统设置/系统缓存或软件版本问题，建议卸载客户端重新安装。可以参考 [机场常见连接超时问题排查](/troubleshooting/airport-connection-timeout) 进行深入除错。
2. **咨询服务提供商**：带上你的测试结果，向你所购买的机场客服提交工单。明确告知他们：“我在电信宽带 Wi-Fi 下连接正常，但在联通 5G 下彻底无法连接，且已经修改为 IPv4 APN 并排除了权限问题”。专业的客服往往能从服务端日志看出是握手失败还是 IP 被所在省份的网关拦截。

## 常见问题解答 (FAQ)

**1. 为什么同样是移动卡，我朋友的手机能用机场，我的却不能？**
这通常是因为手机型号和操作系统的差异。不同品牌手机对“后台活动”、“移动数据访问权限”以及“省电策略”的管理机制不同。此外，即使都是中国移动，不同省市甚至不同基站的 QoS（服务质量）策略和 DNS 劫持情况也存在差异。建议首先对比两台手机的代理客户端权限设置和 APN 配置。

**2. 每次从家里出来，切换回 4G/5G 都要重新开关一次代理才行，正常吗？**
这是网络切换导致的常见现象，属于相对正常的软性故障。从 Wi-Fi 切换到移动网络时，设备的本地 IP 和网络接口都会发生改变，部分代理软件未能及时更新虚拟路由表，导致流量进入死胡同。手动开关一次即可强制重新建立正确的路由映射。

**3. 开启代理后，手机顶部的 5G 信号图标有个叹号是怎么回事？**
叹号通常意味着系统检测到“连接到了基站，但无法连接到互联网（通常是无法连通 Google 的验证服务器）”。如果你开启代理后出现了叹号，可能是代理软件配置错误导致全局网络瘫痪，或者是代理接管了系统的探测流量但未能正确代理出去。请检查 DNS 设置和是否误开了全局模式。

**4. 将移动网络的 APN 协议从 IPv4/IPv6 改为纯 IPv4，会让我的日常上网速度变慢吗？**
一般情况下不会。虽然 IPv6 是未来的趋势并在理论上拥有更好的端到端连通性，但目前国内几乎所有主流应用（微信、抖音、淘宝等）均提供极其完善的 IPv4 访问支持。修改为纯 IPv4 主要为了避开代理软件处理 IPv6 时的兼容性 Bug，你的肉眼体验和下载速度基本不会受到影响。

**5. 是不是因为我的机场节点被三大运营商针对性封锁了？**
有这个可能，但不能绝对断言。运营商封锁更多体现在“封锁某个节点的 IP”或“封锁某个协议特征”。如果你的节点在宽带下能用，说明节点的 IP 并未被全面拉黑。在移动网络下失效，大概率是因为移动网络分配的 DNS 无法正确解析节点域名，或者特定运营商的跨网路由太差（例如电信节点在移动 4G 下丢包严重）。

**6. 遇到 5G 下不能用，直接把代理软件切换到“全局模式（Global）”能解决问题吗？**
一般不能，甚至可能起反作用。全局模式会将所有流量（包括国内应用流量）发往海外节点，这不仅无法解决底层由于权限、IPv6 或 APN 导致的连通性故障，反而会因为短时间内产生异常的跨境流量模型而被运营商的防火墙短暂阻断。遇到连接问题，优先排查底层网络设置，而不是盲目切换代理模式。
