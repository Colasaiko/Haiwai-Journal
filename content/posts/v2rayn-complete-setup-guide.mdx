## v2rayN 是什么，和其他代理客户端有什么不同

v2rayN 是一款长期活跃在 Windows 平台的开源图形界面代理客户端，由 GitHub 用户 2dust 维护。它本质上是一个"壳"——底层调用 Xray-core 或 v2fly-core 作为实际处理流量的引擎，而 v2rayN 自身负责提供可视化操作界面、订阅管理和系统代理配置等功能。

与 Clash 系列客户端（如 Clash Verge Rev、Clash for Windows）相比，v2rayN 有几点明显的定位差异：

**协议支持广度方面**，v2rayN 原生支持 VMess、VLESS、Trojan、Shadowsocks、Socks、HTTP 等主流协议，对 VLESS+XTLS-Vision、VLESS+Reality 等 Xray 独有特性的兼容度更高，因为 Xray-core 本身就是 Xray 项目的官方核心。

**配置粒度方面**，v2rayN 适合想要精细调整入站/出站规则、DNS 策略或路由规则的用户。它暴露的配置选项比大多数 Clash GUI 更底层，但入门门槛也稍高一些。

**费用方面**，v2rayN 完全免费，无订阅限制、无设备数限制，非常适合作为长期主力工具使用。它的程序本体不到 10MB，不依赖 Electron，对系统资源的占用极低。

**平台方面**，v2rayN 只面向 Windows，不提供 macOS 或 Linux 版。如果你需要多平台统一管理，Clash Verge Rev 或许是更合适的选择，关于 Clash 的订阅导入方式可以参考 [Clash 订阅导入教程](/clash/how-to-import-clash-subscription)。

如果你的机场主要提供 VLESS+Reality 节点，或者你偏好在 Windows 上使用一款轻量、无 Electron 负担的界面工具，v2rayN 是目前最主流的方案之一。

## 下载与安装：从 GitHub Releases 到解压运行

### 获取安装包

访问 v2rayN 的 GitHub Releases 页面（搜索 "2dust v2rayN github" 即可找到），找到最新版本（带有 `Latest` 标签的那一条）。你会看到多个压缩包，常见的文件名格式如下：

- `v2rayN-With-Core.zip`：**推荐新手下载**，已内置 Xray-core，解压即可运行。
- `v2rayN.zip`：仅包含 GUI 壳，不含核心文件，需要自行下载 Xray-core 或 v2fly-core 并放入程序目录。

对于大多数用户，直接下载 `v2rayN-With-Core.zip` 是最省事的选择，省去单独配置内核的步骤。

### .NET 运行时依赖说明

v2rayN 6.x 及以上版本基于 .NET 6 或更高版本构建。如果你运行后看到"未找到 .NET 运行时"的错误弹窗，说明系统缺少对应的 .NET Desktop Runtime。解决方法：

1. 前往 Microsoft .NET 官方下载页面，选择对应版本的 **Windows Desktop Runtime**（注意不是 SDK，也不是 ASP.NET Core Runtime）。
2. 安装后重新运行 `v2rayN.exe`，通常不需要重启系统即可生效。

Windows 11 系统一般已经预装了 .NET，出现此问题多见于老旧的 Windows 10 LTSC 版本。

### 解压与首次运行

将压缩包解压到一个**没有中文路径、没有空格**的目录，例如 `D:\Proxy\v2rayN`。中文路径有时会导致核心加载失败。双击 `v2rayN.exe` 即可启动，无需安装程序，也不会向注册表写入复杂配置（除非你手动设置开机自启）。首次运行后，系统托盘区会出现一个 V 形图标，这就是 v2rayN 的主要入口。

## 首次启动与界面认知

### 系统托盘与主窗口

v2rayN 启动后默认最小化到任务栏托盘。右键点击托盘图标可以快速切换代理模式、访问设置或退出程序。双击托盘图标打开主窗口，界面分为几个核心区域：

- **顶部菜单栏**：包含"服务器"（节点管理）、"订阅分组"、"参数设置"、"帮助"等菜单项。
- **服务器列表**：主窗口中央区域，列出当前所有节点，显示别名、协议类型、地址、端口和测试延迟。
- **底部状态栏**：实时显示当前运行的核心版本（如 Xray-core v1.x.x）、代理模式（系统代理/TUN/无代理）以及当前活跃节点的名称。
- **日志窗口**：通过菜单"帮助 → 查看运行日志"或按快捷键 `Ctrl+Alt+L` 打开，实时输出核心的连接日志，是排查连接问题时最重要的参考界面。

### 语言与外观调整

打开"参数设置 → 基础设置"，可以切换界面语言（支持中文简体/繁体/英文）、调整字体大小以及设置主题颜色。如果界面显示乱码，在"基础设置"中强制指定语言为"中文简体"通常可以解决。

此外，主窗口支持调整各列的宽度和显示顺序，如果节点别名太长导致地址列被挤压，直接拖拽列分隔线即可。

## 订阅分组：添加订阅 URL、更新与管理

### 添加订阅 URL

在主菜单点击"订阅分组 → 订阅分组设置"（或按快捷键 `Ctrl+O`），弹出订阅管理窗口。点击左下角的"+"按钮新建一个分组，在"地址（URL）"一栏粘贴机场提供的订阅链接，"备注"栏填写一个方便识别的名称（如"主用机场"或"备用节点"），其他参数保持默认后点击"确定"保存。

### 更新订阅

回到主窗口后，点击菜单"订阅分组 → 更新全部订阅（不使用代理）"。首次更新时，因为还没有可用节点，需要在直连环境下能访问订阅 URL 才能拉取节点数据。如果订阅链接本身需要代理才能访问，可以先手动添加一个 vmess/vless 节点建立初始连接，再选择"更新全部订阅（使用代理）"。

> 如果你在更新订阅时持续遇到失败提示，可以参考 [Clash 订阅更新失败排查](/clash/clash-subscription-update-failed) 中的通用思路，部分原因和解决方式在不同客户端间是相通的。

### 分组管理技巧

当你订阅了多个机场时，每个机场的节点会分别显示在服务器列表左侧的分组标签下，切换标签即可只查看该机场的节点。

你可以在订阅管理窗口拖拽调整分组顺序，也可以为每个分组设置不同的更新间隔（如每 12 小时自动静默更新一次）。右键某个分组还可以选择"删除当前分组所有节点"，便于在订阅更新后清理失效的旧节点。服务器列表支持按延迟、协议类型、节点名称排序，多选节点后可以批量测速，效率较高。

## 核心管理：Xray-core 与 v2fly-core 的区别

v2rayN 支持同时管理多个核心文件，在"帮助 → 检查更新"中可以分别更新这两个核心。理解它们的差异有助于选择正确的版本：

### v2fly-core（原版 V2Ray）

v2fly-core 是 V2Ray 项目的社区延续版本，对 VMess 和早期 VLESS 的支持最为稳定，配置文件格式与历史文档完全兼容。如果你的机场节点主要是 VMess 协议，使用 v2fly-core 是稳妥的选择，出现问题时相关中文文档也更多。

### Xray-core

Xray-core 由 XTLS 团队（现 Xray-core 社区）维护，相当于 v2fly-core 的超集。它在以下方面具有明显优势：

- 支持 XTLS-Vision、VLESS+Reality 等新型抗检测传输协议，这些是 v2fly-core 不具备的。
- 在高并发连接场景下性能更优，整体吞吐量较高。
- 对新协议特性的迭代速度更快，通常新协议都首先在 Xray-core 实现。

**建议默认使用 Xray-core**，除非机场明确要求使用特定版本的 v2fly-core。

### 更新内核的操作

打开"帮助 → 检查更新 → Xray-core"，v2rayN 会自动从 GitHub 下载最新版核心文件并替换当前版本。更新后无需重启 v2rayN，底部状态栏的版本号会立刻刷新。如果 GitHub 访问慢，可以在"参数设置 → 基础设置"中勾选"通过代理更新订阅/核心"，前提是当前有可用节点且处于代理模式。

## 系统代理模式详解

v2rayN 提供三种主要代理模式，通过托盘右键菜单或主窗口底部快速切换：

### 自动配置系统代理

这是日常使用最频繁的模式。开启后，v2rayN 会修改 Windows 的"Internet 选项"中的代理服务器设置，将本机 HTTP 和 HTTPS 流量指向 v2rayN 在本地监听的端口（默认为 HTTP 代理 `127.0.0.1:10809`，Socks5 代理 `127.0.0.1:10808`）。Chrome、Edge、Firefox（如果设置为跟随系统代理）等主流浏览器会自动受影响，无需额外配置。

这个模式的局限性在于：它只能覆盖遵循系统代理设置的应用程序。命令行工具（如 `curl`、`git`、`npm`）、UWP 应用、某些游戏以及直接使用 socket 连接的程序，默认不走这个代理。

### 不改变系统代理

这个模式下，v2rayN 只在后台监听本地端口，不修改 Windows 的系统代理设置。适合搭配 SwitchyOmega 等浏览器插件精准控制特定标签页走代理，或者配合 Proxifier 这类全局代理工具使用，由外部工具决定哪些应用走 v2rayN 的本地端口。

### 清除系统代理

点击后 v2rayN 会将 Windows 系统代理恢复为空（不使用代理），v2rayN 进程本身仍在运行。适合临时需要完整直连时使用，不必关闭整个程序。

## PAC 模式 vs 全局代理

在"参数设置 → 系统代理"或托盘菜单中，你可以选择系统代理的具体工作方式：

### PAC 模式（自动代理配置）

PAC 模式下，v2rayN 会在本地托管一个 PAC 脚本文件，其中维护了一份需要走代理的域名列表。浏览器在每次发起请求前会先查询这个 PAC 脚本，判断当前域名是否应该走代理。

**适合场景**：希望国内网站直连、海外被墙网站走代理的轻量分流需求。PAC 文件体积小、响应快，对本地带宽几乎没有额外消耗。局限是 PAC 规则列表需要定期更新，面对新增被墙域名时存在滞后。

### 全局代理

全局模式下，所有通过系统代理接管的 HTTP/HTTPS 流量都会强制走代理出口，不经过 PAC 规则判断。但这不意味着国内网站一定走代理——在 v2rayN 的 Xray-core 路由规则中，你可以另外配置"绕过局域网和大陆地址"规则，使得访问国内 IP 和域名时在代理内部直接走直连出站，实现实质上的智能分流。

**实际推荐**：日常使用选择**全局代理 + 路由规则绕过大陆**的组合，分流效果比单纯依赖 PAC 更稳定，也避免了 PAC 规则遗漏域名的问题。排查连接问题时才临时切换到全局代理（不加路由规则），确保排除 PAC 干扰。

## TUN 模式：接管全部系统流量

### 什么是 TUN 模式，为什么需要它

系统代理只能覆盖"听话"的应用程序。命令行中执行 `curl`、`git clone` 或 `npm install` 时，这些工具通常并不读取 Windows 系统代理设置，因此即使 v2rayN 处于代理模式，它们也在走直连。游戏客户端的情况类似。

TUN 模式通过在 Windows 中创建一块虚拟网卡（tun 设备），在网络层（第三层/IP 层）接管所有出站流量。这意味着不管什么应用程序，只要它往外发数据包，都会经过这张虚拟网卡，然后被路由到 Xray-core 进行处理。

### 开启 TUN 模式的步骤

**第一步：以管理员身份运行 v2rayN**

右键 `v2rayN.exe`，选择"以管理员身份运行"。这是 TUN 模式正常工作的硬性前提——普通用户权限无法在 Windows 中创建虚拟网卡，尝试启动时会报权限错误。

如果你想让 v2rayN 每次双击都自动提权，可以右键 `v2rayN.exe` → "属性" → "兼容性" → 勾选"以管理员身份运行此程序" → 点击"应用"。

**第二步：配置 TUN 设置**

打开"参数设置 → Tun 模式设置"，按以下建议配置：

- **启用 Tun 模式**：勾选。
- **堆栈类型（Stack）**：选择 `system`（利用 Windows 原生协议栈，稳定性高，推荐大多数用户使用）。如果遇到兼容性问题，可以切换到 `gvisor`（纯用户态实现，兼容性更广但性能略低）。
- **自动设置 Tun DNS**：建议勾选，让 v2rayN 接管系统 DNS 请求，防止 DNS 污染。
- **绕过局域网**：建议勾选，避免访问路由器管理页面或局域网打印机等设备时产生异常。

点击"确定"后，v2rayN 会自动在 Windows 系统中创建虚拟网卡。你可以在 Windows 的"网络连接"列表中看到一张新增的虚拟网卡条目。

### TUN 模式使用注意事项

开启 TUN 后，命令行的 `curl`、`git clone`、`pip install`、`npm install` 等工具会自动走代理，无需额外设置 `HTTP_PROXY` 环境变量。游戏客户端的登录和好友列表流量也会被接管，有助于解决部分游戏登录被限制的问题。

同时运行其他 VPN 软件（如 WireGuard 客户端、公司 VPN）时，可能产生路由表冲突，建议一次只开一个 TUN 类工具。退出 v2rayN 后，虚拟网卡会被系统自动移除，不留残留。

## 节点延迟测速与真实速度测试

### 延迟测试（Ping 测试）

右键服务器列表中的任意节点，选择"测试服务器延迟（Ping）"，v2rayN 会向该节点地址发起 TCP 连接并记录往返时间。这个数值反映的是**你的网络到代理服务器之间的网络距离**。

延迟数值不能直接等同于上网速度——一个延迟 120ms 的 IPLC 专线节点，其出口到目标网站的线路质量往往远好于一个延迟 40ms 但出口严重拥塞的普通节点。延迟低只说明握手快，实际带宽还受出口拥塞情况影响。

### 真实连接速度测试

在主菜单选择"服务器 → 测试服务器速度（Real Delay）"，v2rayN 会通过当前节点实际发起一个完整的 HTTP 请求，记录完整的响应耗时。这个测试比单纯的 Ping 更贴近真实使用体验，因为它走了完整的代理链路。

如果想测试下载带宽，可以在开启系统代理后，用浏览器访问 `speed.cloudflare.com` 或 `fast.com`，这两个网站会通过当前代理节点测量下载速率，结果直观可靠。

### 批量测速技巧

在服务器列表中按住 `Ctrl` 或 `Shift` 多选节点，右键选择"测试服务器延迟"，即可批量测试选中的所有节点。测试完成后，点击列标题中的"延迟"列进行升序排序，最快的节点会显示在最顶部，方便直接切换。

## 路由规则配置：绕过大陆与自定义规则

### 内置路由预设

在"参数设置 → 路由设置"中，v2rayN 提供了几个开箱即用的路由预设：

- **绕过大陆（推荐）**：国内 IP/域名直连，境外流量走代理，局域网地址直连。这是日常使用的最优默认设置。
- **全局**：所有流量走代理出站，不进行任何分流。
- **自定义**：完全手动配置每一条出入站规则，适合进阶用户。

"绕过大陆"预设内部使用了 `geoip:cn` 和 `geosite:cn` 规则集，这两个文件会随 v2rayN 程序一起分发，也可以手动更新到最新版本（位于 `bin/xray/` 目录下）。

### 手动添加自定义规则

如果你需要让特定域名走特殊出口（比如让 Steam CDN 走直连但让 GitHub 走代理），可以在"路由设置"中手动添加规则条目。规则格式示例：

- `domain:steamcommunity.com` → 出站选择 `direct`（直连）
- `geoip:us` → 出站选择 `proxy`（代理）
- `domain:github.com` → 出站选择 `proxy`（代理）

规则匹配顺序是从上到下，第一条匹配的规则生效。因此更精细的规则（如单独的域名规则）应该放在更宽泛的规则（如 `geosite:cn`）的上方，避免被宽泛规则提前命中。

## DNS 防污染设置

DNS 污染在国内网络环境中相当普遍。当你向国内运营商 DNS（如电信的 `114.114.114.114`）查询 Google 的 IP 时，返回的可能是一个虚假地址或者根本无法连接的 IP，导致即使代理隧道建立成功，域名解析的结果也是错的，网页依然打不开。

在"参数设置 → DNS 设置"中，v2rayN 通过 Xray-core 提供了以下防污染策略：

### 分流 DNS（推荐）

配置两套 DNS 服务器：

- **国内 DNS**（处理直连流量的解析）：如 `223.5.5.5`（阿里云）或 `119.29.29.29`（腾讯 DNSPod）。这些服务器在国内访问延迟低，解析国内域名结果准确。
- **境外 DNS**（处理代理流量的解析）：如 `8.8.8.8`（Google DNS）或 `1.1.1.1`（Cloudflare DNS）。这些查询通过代理隧道发出，因此不会被国内防火墙干扰，解析结果是真实的。

分流 DNS 配置完成后，访问国内网站用国内 DNS 解析（速度快、延迟低），访问境外网站用境外 DNS 解析（结果准确、无污染），两者互不干扰。

### DoH（DNS over HTTPS）

如果觉得配置分流 DNS 比较复杂，可以直接在 DNS 设置中填写 DoH 地址，如 `https://dns.cloudflare.com/dns-query`。DoH 查询使用 HTTPS 加密传输，运营商无法在传输途中篡改查询结果，是防污染的简便方案。代价是每次 DNS 解析的耗时比 UDP DNS 略高，对首次加载网页的速度有轻微影响。

## 自动启动与最小化到托盘

### 开机自启设置

在"参数设置 → 基础设置"中，勾选"开机自动启动"，v2rayN 会将自身添加到 Windows 的"启动"项中（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 注册表键），系统启动时自动运行。

建议同时勾选"启动时最小化到系统托盘"，这样开机后 v2rayN 会静默进入后台，不会弹出主窗口打扰正常使用流程。

### 关闭按钮行为

点击主窗口右上角的 X 关闭按钮时，v2rayN 默认只是将主窗口最小化到托盘，并不退出程序（代理仍在运行）。这是绝大多数代理工具的标准行为，避免用户误关导致代理中断。

如果需要真正退出，右键托盘图标选择"退出"即可。如果你更习惯点 X 就退出，可以在"参数设置 → 基础设置"中将"关闭主窗口时"的行为改为"直接退出程序"。

## 常见错误与排查指南

### 所有节点延迟测试都显示 Timeout

**可能原因**：当前网络环境阻断了对代理服务器地址的直接连接，或者节点批量失效。

**排查步骤**：先更新订阅获取最新节点列表；打开日志窗口（`Ctrl+Alt+L`）观察错误信息，`i/o timeout` 说明服务器地址不通，`connection refused` 说明端口有误或服务未启动；换不同地区节点测试，如果个别节点可用则说明是部分 IP 被封锁而非客户端问题。如果所有节点都超时，联系机场客服确认服务状态是最快的解决路径。

### TUN 模式启动报错：需要管理员权限

这是 TUN 模式最常见的报错。解决方法：右键 `v2rayN.exe` → "属性" → "兼容性" → 勾选"以管理员身份运行此程序" → 点击"应用"，之后每次双击都会自动提权运行。

如果不想每次都弹出 UAC 弹窗确认，可以通过 Windows 任务计划程序将 v2rayN 设置为"以最高权限运行"的启动任务，开机自启时不会再触发 UAC 提示。

### 连接建立成功但网页打不开

这通常是 DNS 污染或路由规则配置错误导致的。检查思路：打开浏览器开发者工具（F12）的 Network 标签，查看请求是否卡在 DNS 解析阶段；尝试直接用 IP 地址访问某个境外服务，如果 IP 可以访问但域名不行，基本确认是 DNS 问题；在 DNS 设置中启用远程 DNS 解析或改用 DoH 地址。

### v2rayN 关闭后系统网络异常（无法上网）

这是系统代理没有被正确清除的经典问题。手动修复：打开 Windows 设置 → 网络和 Internet → 代理，将"使用代理服务器"开关关闭。或者重新打开 v2rayN，在托盘菜单中选择"清除系统代理"后再正常退出，后续就不会残留代理设置。

## v2rayN 与 Clash Verge Rev 的定位对比

很多用户在这两款工具之间纠结，以下是基于实际使用场景的分析：

| 维度 | v2rayN | Clash Verge Rev |
|------|--------|-----------------|
| 协议支持 | VMess / VLESS / Trojan / SS / Reality，Xray 特性完整 | 依赖 Mihomo core，对 Reality 的支持在 2024 年后趋于完善 |
| 配置方式 | 手动填写节点参数或订阅导入，路由规则图形化设置 | 订阅导入为主，支持 Clash YAML 格式，覆写规则便捷 |
| 规则生态 | 路由规则偏底层，主要依靠 geosite/geoip 数据库 | Clash 规则集生态丰富，社区维护的规则资源更多 |
| 界面 | 传统 WinForms 风格，轻量无 Electron，内存占用极低 | 基于 Tauri 构建，界面现代，内存占用稍高 |
| 适合人群 | 偏好底层控制，机场以 VLESS+Reality 为主，不喜欢 Electron 的用户 | 习惯 Clash 配置格式，机场提供 Clash 订阅，需要策略组分流的用户 |

如果你的机场提供标准 Clash 格式订阅，且订阅中已经内置了策略组，Clash Verge Rev 可以做到"导入即用"，无需手动配置路由规则。如果机场以 Xray 系协议为主，或者你想精细控制每一条路由出口，v2rayN 更适合你的需求。

更多工具的横向对比和选用建议，可以参考 [代理工具总览](/tools)；刚开始接触代理的用户可以先阅读 [新手入门指南](/start-here) 了解基本概念。

## 常见问题解答（FAQ）

### Q1：v2rayN 支持 Shadowsocks 2022（SS2022）协议吗？

支持。v2rayN 搭配最新版 Xray-core 可以正常使用 SS2022 协议，如 `2022-blake3-aes-128-gcm` 和 `2022-blake3-aes-256-gcm` 等加密方式。添加节点时协议选择 Shadowsocks，在加密方式下拉框中选择对应的 2022 算法即可。如果下拉选项中没有出现 2022 算法，说明当前 Xray-core 版本过旧，需要先更新内核。

### Q2：订阅里有几百个节点，能不能只显示某个地区的节点？

可以。服务器列表上方有一个搜索框，输入关键词（如"日本""JP""🇯🇵"）后，列表会实时过滤只显示节点名称中包含该关键词的条目。另外，在订阅管理中为不同机场设置好备注名称，通过左侧的分组标签切换，也可以只查看特定机场的全部节点。

### Q3：如何让 git clone 或 npm install 走代理？

如果开启了 TUN 模式，这些命令行工具会自动走代理，无需额外操作。如果只用系统代理模式，需要在命令行中手动设置代理环境变量：

```bash
set HTTP_PROXY=http://127.0.0.1:10809
set HTTPS_PROXY=http://127.0.0.1:10809
```

设置完成后，在同一个命令行窗口中执行 `git clone` 或 `npm install` 即可走代理。窗口关闭后环境变量自动消失，不影响其他程序。

### Q4：v2rayN 可以把代理共享给局域网内的手机或其他电脑使用吗？

可以。在"参数设置 → 基础设置"中，将 HTTP 代理和 Socks5 代理的监听地址从 `127.0.0.1` 改为 `0.0.0.0`（监听所有网卡），然后在其他设备的代理设置中填入运行 v2rayN 的电脑的局域网 IP（如 `192.168.1.5`）和对应端口。同时需要确保 Windows 防火墙允许该端口的入站连接，否则局域网设备无法建立连接。

### Q5：更新内核或订阅时反复报"下载失败"怎么解决？

大概率是 GitHub 访问受阻。在"参数设置 → 基础设置"中勾选"通过代理更新订阅/核心"，确保当前有一个可用节点并处于代理模式，再次尝试更新。如果所有节点都已失效，可以用手机开热点后，在热点网络下手动从 GitHub Releases 下载 Xray-core 的 zip 压缩包，将解压后的可执行文件直接放入 v2rayN 程序目录下的 `bin/xray/` 文件夹中替换旧文件即可。

### Q6：节点延迟测试只有 30ms，但实际打开网页很慢，是为什么？

延迟（Ping）测试只衡量 TCP 握手的往返时间，反映的是你的网络到代理服务器的"通道响应速度"。实际网页加载速度还受到：代理服务器到目标网站服务器之间的线路质量、代理服务器的出口总带宽以及是否处于高峰拥塞时段等多重因素影响。一个延迟 150ms 的 IPLC 专线节点，实际下载速度往往远超一个延迟 30ms 但出口带宽严重超售的普通节点。

### Q7：TUN 模式开启后游戏出现延迟增加，怎么处理？

游戏流量经过 TUN 后会多一层 Xray-core 处理开销，如果路由规则配置为"绕过大陆"，国内游戏服务器的流量理论上仍走直连，性能影响有限。如果是海外游戏服务器，延迟增加是正常的——流量经过了代理服务器中转。建议在"Tun 模式设置"中为游戏进程名（如 `LeagueClient.exe`）单独设置进程排除规则，让游戏流量绕过 TUN 走直连。

### Q8：v2rayN 的所有配置文件存在哪里？如何备份迁移到新电脑？

v2rayN 的配置采用免安装设计，所有设置（节点信息、订阅地址、路由规则、参数偏好）均保存在程序目录下的 `guiConfigs` 文件夹中，核心文件为 `guiNConfig.json`。将整个 v2rayN 程序目录打包压缩，复制到新电脑解压后直接双击运行，所有配置完整恢复，无需重新输入任何内容，是迁移时最省事的方式。

### Q9：v2rayN 能同时连接多个节点吗？

v2rayN 本身一次只激活一个出站节点（即当前选中的"活跃节点"），不支持类似 Clash 策略组那样同时维护多个出站并按规则分发流量。如果你需要同时让不同流量走不同节点（如流媒体走 A 节点、普通浏览走 B 节点），建议切换到 Clash Verge Rev 并使用策略组功能，这种场景是 Clash 更有优势的地方。

### Q10：v2rayN 和某些杀毒软件冲突，被报毒怎么办？

v2rayN 和 Xray-core 因为涉及底层网络操作（创建虚拟网卡、监听端口）以及 GitHub 下载渠道，有时会被 Windows Defender 或第三方杀毒软件误报。解决方法是在杀毒软件中将 v2rayN 的程序目录添加到"排除项"（白名单），之后就不会再被拦截。强烈建议只从 GitHub 官方 Releases 页面下载，不要从第三方渠道获取安装包，避免真的下载到包含恶意代码的版本。
