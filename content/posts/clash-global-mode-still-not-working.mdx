很多用户在使用 Clash 时会遇到这样一个令人头疼的问题：明明已经把代理模式切换到了 **Global（全局）** 模式，但打开浏览器依然无法访问任何网页，甚至连国内的网站也打不开了。

不少人对“全局模式”存在一个误解，认为只要开了全局，网络就一定会自动走代理、一定能翻墙成功。事实上，**Global 只是 Clash 的一种路由策略（Routing Policy），它仅仅表示“让所有流量都强制走你指定的某一个节点或策略组”，并不代表这个节点本身一定是可用、连通的**。如果节点已死，或者系统的网络设置没有正确接管流量，那么全局模式不但不能帮你翻墙，反而会导致所有网页都打不开（因为所有流量都被强制送进了一个黑洞）。

本文将从原理出发，为你提供一套完整的、循序渐进的故障排查指南。如果你在开启 Global 模式后依然无法上网，请严格按照以下步骤进行检查。

---

## 一、理解 Global 模式的本质

在 Clash 中，主要有三种模式：
1. **Rule (规则模式)**：根据配置文件中的规则，判断流量是直连（DIRECT）、走代理（PROXY）还是拦截（REJECT）。
2. **Global (全局模式)**：无视所有规则，将所有流量强制交由某一个特定的节点或策略组处理。
3. **Direct (直连模式)**：无视所有规则，所有流量直接访问，不经过任何代理节点。

当你切换到 Global 模式时，Clash 会在面板（通常是 Proxies 标签页下的 Global 分组）要求你选择一个节点。**此时，你的所有网络请求（无论国内国外）都会被发送到你选中的这个节点。** 如果这个节点：
- 服务器已经宕机
- 端口被封
- 协议或密码错误
- 机场流量耗尽或订阅过期

那么你的所有请求自然都会失败，表现出来的就是“什么网页都打不开”。

## 二、故障排查步骤：由浅入深

### 1. 检查当前选中的节点是否可用

这是最常见的原因。既然全局模式是把流量全塞给一个节点，那么这个节点必须得是好的。

**排查方法：**
1. 打开 Clash 客户端界面，进入 **Proxies（代理）** 页面。
2. 找到 **Global** 策略组。
3. 点击右下角的闪电图标（或“延迟测速”按钮），对 Global 组内的节点进行测速（URL Test）。
4. 如果所有节点都显示 `Timeout`（超时）或红色的错误，说明你的节点全部不可用。
5. **解决方法**：更新订阅。如果更新订阅后测速依然全部超时，请登录你的机场官网，检查是否流量耗尽、套餐过期，或者机场本身正在遭受攻击/维护。尝试更换另外一个机场的节点测试。

### 2. 检查系统代理 (System Proxy) 是否成功开启

有了好的节点，还需要系统把流量交给 Clash。Clash 通常通过修改操作系统的“系统代理设置”来接管 HTTP/HTTPS 流量。

**排查方法：**
1. 检查 Clash 客户端上的 **System Proxy（系统代理）** 开关是否已经打开。
2. 如果已经打开，但依然上不了网，可能是系统代理设置没有生效，或者被其他软件篡改了。
3. **在 Windows 上**：按下 `Win + I` 打开设置 -> 网络和 Internet -> 代理。检查“使用代理服务器”是否被开启，并且地址和端口是否与 Clash 设置的一致（通常地址是 `127.0.0.1`，端口是 `7890`）。
4. **在 macOS 上**：打开 系统偏好设置 -> 网络 -> 选择当前网络（如 Wi-Fi） -> 高级 -> 代理。检查 “Web 代理 (HTTP)” 和 “安全 Web 代理 (HTTPS)” 是否被打勾，地址和端口是否正确。
5. **冲突软件**：如果你同时开启了其他代理软件、加速器（如 UU 加速器）、甚至某些安全软件，它们可能会劫持或清空代理设置。请暂时关闭这些软件。

### 3. 检查 TUN 模式 / 虚拟网卡状态

如果你想让不支持系统代理的软件（如某些游戏、命令行工具）也能走代理，或者遇到系统代理频频失效的情况，你可能会开启 **TUN 模式**。如果 TUN 模式配置错误，也会导致断网。

**排查方法：**
1. 检查 Clash 的 **TUN** 开关是否开启。
2. 如果开启了 TUN，请确保你以**管理员权限**（Windows）或**Root 权限**（macOS）运行了 Clash。
3. 尝试暂时关闭 TUN 模式，仅使用 System Proxy，看看网页是否能打开。如果关闭 TUN 后恢复正常，说明是 TUN 模式的网卡冲突或路由表配置问题。你可以尝试重置网络（Windows 下使用 `netsh winsock reset`），或者重启电脑，然后重新配置 TUN。

### 4. 检查 DNS 设置是否冲突或污染

DNS（域名解析系统）是将网址转换为 IP 地址的服务。如果 DNS 解析失败，浏览器就会提示“找不到服务器 IP 地址”。在使用 Clash 的全局模式时，DNS 请求也受到 Clash 的接管。

**排查方法：**
1. 你的 Clash 配置文件中，DNS 设置部分（`dns:`）可能存在不合理的上游服务器。
2. 尝试在终端或命令提示符中 `ping google.com` 和 `ping baidu.com`。如果提示“找不到主机”，大概率是 DNS 问题。如果能解析出 IP，但就是打不开网页，则是连接问题。
3. 如果你使用了第三方防污染 DNS 工具，或者在操作系统的网卡上强行写死了某个失效的 DNS（比如把 DNS 设成了已经被停用的某个小众 IP），会导致 Clash 无法正确接管 DNS。
4. **解决方法**：将网卡的 DNS 设置改为“自动获得 DNS 服务器地址”；如果你懂得修改 Clash 配置文件，可以检查 `dns.enable` 是否为 `true`，以及 `nameserver` 列表是否包含常见的公共 DNS（如 `114.114.114.114`，`8.8.8.8`，`223.5.5.5`）。

### 5. 浏览器本身的代理插件或安全设置

有时候，系统代理没问题，节点也没问题，但就是某个特定的浏览器打不开网页。

**排查方法：**
1. **代理插件冲突**：如果你在 Chrome/Edge 中安装了 SwitchyOmega 等代理管理插件，请检查插件的设置。如果插件设置为“直接连接”或指向了一个错误的端口，那么浏览器就会无视操作系统的系统代理设置。请将插件设置为“使用系统代理”或直接禁用该插件。
2. **安全 DNS (DoH)**：现代浏览器（如 Chrome, Firefox）内置了“安全 DNS”功能。如果开启了强制使用特定 DoH 提供商，可能会绕过 Clash 的 DNS 处理，导致解析异常。可以在浏览器设置中搜索“安全 DNS”并尝试暂时关闭，看是否恢复。

### 6. 防火墙与安全软件拦截

某些过于严格的杀毒软件或系统防火墙，可能会将 Clash 的内核进程（如 `clash-core.exe` 或 `clash-meta.exe`）识别为风险并拦截其网络请求。

**排查方法：**
1. 检查 Windows Defender、火绒、360 等安全软件的拦截日志，看是否屏蔽了 Clash。
2. 尝试暂时退出这些安全软件，重启 Clash，测试是否能上网。如果能，请将 Clash 所在的文件夹加入杀毒软件的白名单。
3. 检查 Windows 防火墙，确保允许 Clash 通过公共和专用网络。

### 7. 检查配置文件与订阅本身的问题

有时候，机场提供的订阅链接存在语法错误，或者该配置文件不兼容你当前使用的 Clash 内核（比如机场使用了大量 Clash Meta 特有的语法，而你使用的是原版 Clash Premium 内核）。

**排查方法：**
1. 查看 Clash 客户端的日志（Logs）。如果有大量的红色 Error，通常意味着解析配置文件失败，或者内核在运行中遇到了致命错误。
2. 尝试新建一个配置文件，只保留最基础的节点信息，或者联系机场客服，确认他们的订阅链接是否完全适配你当前的客户端版本。

---

## 总结：排查流程速记口诀

面对“开了全局还是打不开网页”，不要慌，牢记以下顺序：

1. **测节点**：节点全红测速不通？换节点、更订阅。
2. **查系统**：System Proxy 开没开？Windows/macOS 设置里是否同步生效。
3. **看插件**：浏览器 SwitchyOmega 是否作祟？DoH 是否冲突。
4. **排网卡**：TUN 模式是否冲突？退出 TUN 试试系统代理。
5. **顾安全**：杀软、防火墙有没有把 Clash 悄悄拦截。

全局模式（Global）不是魔法，它只是一个“强制执行命令”的开关。确保你的“执行人”（节点）是活着的，且你的“指令”（代理设置）准确传达到了系统，才是畅游网络的前提。希望这篇文章能帮你快速定位问题，恢复顺畅的网络体验。
